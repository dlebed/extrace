extrace

Tracing for heterogeneous multi-core SoCs, where every core runs its own firmware and the shared memory is not cache-coherent. Every core writes compact records into its own lock-free ring. One dispatcher reads them all, and the host decodes them.

  • 2–8 byte records
  • no locks between cores
  • per-function ftrace flavors
  • caller recording
  • ARMv7-M · RV32
  • freestanding, no dependencies

Why extrace

Built for SoCs with several subsystems, such as DSPs, MCUs and accelerators, each running its own firmware image. The cores share memory but no locks and no caches.

rings

Many producers, one dispatcher

Each core owns a single-producer, single-consumer ring with free-running indices. There are no cross-agent atomics, and each shared word has exactly one writer.

cost

Cheap when off, short when on

A disabled event costs one load, a bit test and a branch, and its arguments are not evaluated. Only pointer arithmetic runs with interrupts masked.

lifecycle

Restart in any order

Producer and consumer initialize and re-initialize in any order and at any time, from random or consistent shared memory.

loss

Drops are counted exactly

When a ring is full, the newest records are dropped instead of blocking. The count is reported in-band as a LOST record.

printf

Deferred printf

The device logs a 16-bit call-site ID and binary arguments. Format strings stay in the ELF, and the host does the formatting.

port

One header to port

Timer, critical section, barriers and doorbells are inline hooks in one extrace_port.h. Builds with gcc and clang, warning-free.

Function entry tracing, one flavor per function

Build with -fpatchable-function-entry. At run time the platform patches the NOP pad of each function it wants traced into a call to one trampoline entry, chosen per function. Because the flavor is the entry the patch calls, no instructions decide it at run time.

patching

Safe to patch while the code runs

extrace_ftrace_patch(pc, flavor) checks the pad first, then rewrites it in an order where every intermediate state is a valid program. It also changes a flavor in place, or restores the NOPs with EXTRACE_FTRACE_OFF. A wrong address is refused before anything is written.

footprint

No tables on the device

A record carries the return address, relative to EXTRACE_CFG_FTRACE_BASE, and the host maps it back to the function through the ELF. A linker fragment keeps the compiler's site table in the ELF only.

caller

Who called it

With EXTRACE_CFG_FTRACE_CALLER=1, any function can be patched with a CALLER flavor. The trampoline passes the caller's return address from ra (RV32) or ip (ARM), and the record gains one uvarint.

switch

One global switch

Tracing is on while the mask bit of system event FTRACE is set, and a consumer flips it like any other event. While it is off, a patched function runs only the trampoline's test: 6 instructions on RV32, 9 on Cortex-M4.

Compact wire format, plain consumer API

Records are a varint header, an optional 32-bit timestamp delta and the payload. Wire format version 1 includes the short FTRACE and FTRACE_CALLER shapes, which have no length field.

FTRACE ARGS(1) with caller: 9 bytes
42hdr19tsd06len00signC7 34addr93 18caller07a0

System event 8, kind INTS. Here addr is the return address minus ftrace_base, which the stream's INFO record carries.

extrace_cons / extrace_disp

Dispatcher with pluggable sinks

Attach each ring with extrace_cons_attach() and register it with extrace_disp_add_ring(), then call extrace_disp_poll(). Bulk sinks forward raw chunks without copying, for example to PCIe or USB. Record sinks receive parsed, filtered events, for example for UART text or statistics.

extrace_rec

Decoder helpers

extrace_dec_next() walks records. extrace_rec_ints() restores signedness, and extrace_rec_ftrace() returns the address, the caller and the argument registers of any function record, whatever its shape. extrace_ctl_ev_set() turns events on and off, function tracing included.

Quick start

The library is compiled per firmware image, so the image's port header, event catalog and configuration apply.

CMakeLists.txt

include(extrace/cmake/extrace.cmake)
enable_language(ASM)
extrace_add_image(fw_a
    PORT_DIR    port      # extrace_port.h
    EVENTS_DIR  events    # extrace_events.def
    COMPONENTS  prod
    FTRACE_ARCH armv7m)   # or rv32; optional
target_link_libraries(fw_a.elf PRIVATE fw_a::extrace)

events/extrace_events.def

EXTRACE_GROUP(CORE, 1)
EXTRACE_EV(RX_PKT, INTS,   ON, CORE, "len:u port:u")
EXTRACE_EV(LOG,    PRINTF, ON, CORE, "")

firmware

#include "extrace.h"

extrace_prod_init(&cfg);          /* any time, any order */

EXTRACE_INTS(RX_PKT, len, port);   /* 1-16 integers */
EXTRACE_PRINTF(LOG, "rx %u on %u", len, port);

/* host command: trace f() with 2 args and its caller */
extrace_ftrace_patch(pc_of_f,
    EXTRACE_FTRACE_ARGS(2) | EXTRACE_FTRACE_CALLER);

extrace_prod_poll();               /* periodic, one task */

build and test

cmake --preset test && cmake --build --preset test
ctest --preset test
bench/run.sh       # the numbers on this page
